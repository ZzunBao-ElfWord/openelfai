# 作品分享修复（2026-10-30）

## 原因与范围

原作品分享只将前40字传入AI资料卡分享，没有交接该作品的视频。旧“已绑定/已授权发布”状态仅为本机时间记录，并非第三方OAuth授权。

- 世界页、视频信息流改为分享选中的作品：原图、原MP4或完整文字。
- 安卓抖音使用现有官方SDK的图片/视频编辑发布流程，与旧资料卡的好友/日常分享分离；文字作品生成完整文字图，过长明确提示复制全文，不截断。
- 快手、微信、B站在安卓通过系统定向分享交接素材，是否有接收入口取决于对应客户端。失败提示并询问是否选择系统分享，不把视频悄悄降级为文字。
- WorkBuddy通过系统分享自行选择；不代表其提供OAuth或直接发布API。
- iOS目前交给系统分享面板，不声称已实现抖音原生作品发布。旧iOS资料卡SDK不变。
- 小红书按用户要求暂缓接入，新作品面板不列出该平台；既有资料卡渠道不删除。
- 旧本地记录保留，改称“常用”并优先排序，不再要求预绑定或声称获得发布授权。
- 保留原AI资料卡/链接分享，不修改验证码、支付、推送、CDN、服务器环境或数据库。

## 安全与交互

只下载白名单HTTPS域名的world-assets素材，不发送登录凭据、不跟随重定向；上限50MiB，并检查图片/MP4格式。提供取消下载，不在后台自动发布。抖音单次交接前需明确同意。完整文案带AI生成提示与原有AI落地页链接，但目标平台是否保留文案由其决定；用户仍须在目标平台核对AI标识。

“已交接”不代表“已发布”。用户最终确认发布；不记录伪造的发布成功状态。

## 验收边界

本地完整Flutter测试165项通过、1项跳过；Dart分析无错误/警告，安卓原生源码编译通过。尚未生成含这些修复的新APK、上传GitHub或部署服务器。旧安装包不改动。下一次按用户要求打包时显示1.0.4（Build22），安卓内部versionCode23。

必须在正式签名安卓真机上验证：抖音开放平台应用分享权限、包名和签名一致；图片/视频进入编辑页、用户取消、最终发布回调。其他客户端也需分别验证是否接收MP4/图片，以及未安装时的提示。未经真机验证不能承诺一键发布已可用。
