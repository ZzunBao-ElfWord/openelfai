# 精灵头像 = 最终铸造形象图（2026-11-01，用户已批准）

## 总原则
头像唯一来源是铸造形象图；首字色块仅为图片加载中/失败的兜底。不做改名、不做自由换头像——名字与头像在创建（铸造）时确定。

## 设计
1. **载荷统一**：服务端所有返回精灵对象的接口统一输出 imageUrl / imageThumbUrl（无图为 null）。
2. **全部精灵走铸造出图，不写死**：
   - UGC 直创 create_elf：创建时同步走 character 渲染管线，用 avatarStyle+avatarPrompt 出图写入精灵记录；渲染失败不阻断创建。
   - 官方 3 只（尘/摩卡/柯）：平台用铸造管线预生成形象（种子脚本），URL 存平台存储而非代码字面量；购买官方精灵时 newElf 复制 URL。
   - 存量迁移：幂等脚本批量补图（官方按种子、UGC 按 style/prompt 渲染）。
3. **中间产物清理**：铸造成功后删除该批次未当选候选图与联系表（按 manifest 清单删、排除最终铸造 key），manifest JSON 保留；删除失败仅记日志。
4. **Flutter 收敛**：ElfAvatar 已图片优先、色块兜底；删除 app_state 与模型中的 avatarUrl 占位机制，数据源收敛为铸造图 URL。
5. **测试**：create_elf 出图落库、官方购买复制、mint 清理（含不误删）、载荷字段；Flutter 模型解析。
